# 資料新鮮度:頁面說的話是不是真的

> 程式碼:[`src/lib/freshness.ts`](../src/lib/freshness.ts)
> 守衛:[`tests/freshness.mjs`](../tests/freshness.mjs)(`npm run test:freshness`)

2026-10-10 的盤點翻出**四處**「頁面宣稱的新鮮度不是真的」。它們看起來是四個獨立的
bug,其實是**同一個病**:**用錯時鐘** —— 顯示的是「這個檔案/這次請求幾點發生」,
而不是「這份資料的內容是什麼時候的」。

---

## 四處實況與處置

| 處 | 畫面上寫的 | 實際用的時鐘 | 真實資料日期 | 處置 |
|---|---|---|---|---|
| `/map` 題材卡 | `核實 2026-10-10` | `map-index.json` 的 `generatedAt`(**prebuild 現生**) | `themes/*.md` 停在 **2026-06-27 ~ 06-30** | 逐題材讀已進版控的 `**策展日期:**` |
| 首頁 `TodayThemes` | `更新於 15:56` | `/api/quote-batch` 的 `fetchedAt`(**報價抓取時間**) | `today-themes.json` 的 `generatedAt` | 兩個時鐘分開印,題材資料過期會標色 |
| 首頁 `MarketFocus` | 三大法人/資券 + 資料日 | — | **2026-07-31**(68 天前) | ⏸ 待裁示(見下) |
| `/news` 每日簡報 | `更新:2026/7/28` | 對的時鐘,但沒說多舊 | **2026-07-27**(74 天前) | 加「(74 天前)」+ 一句話 |

### 🔴 最嚴重的不是過期,是「自我刷新的時間戳」

`/map` 那個欄位每天 build 都會變成「今天」。
**一個每天都在動的數字掛著「核實」,比單純過期更嚴重 —— 它看起來永遠健康。**
過期的資料至少會讓人起疑;自我刷新的時間戳不會。

`TodayThemes` 同理,而且更隱蔽:`fetchedAt` 是報價時間,**永遠是現在**,
於是它**用報價的新鮮度替題材資料背書**。那一步在 workflow 裡還是
`continue-on-error`(失敗不紅燈、舊檔原地留著)——**沒有任何東西會說出來**。

---

## 三條規則

### ① 時鐘要對準被描述的那份資料

報價的時間不可以拿來替題材資料背書。兩份資料就印兩個時間,各自具名:

```
題材資料 2026-10-10 00:43 · 報價 2026-10-10 15:56
```

前綴要有**主詞**。「更新於」沒有主詞,是最容易用錯時鐘的寫法。

### ② 量不到就不要宣稱

解析不出日期 → `display: null` → 呼叫端**整個不顯示**。
退回「部署時間」「現在」或任何其他時鐘,都是把不知道講成知道。
也不要印一個光禿禿的前綴(「更新於 」讀起來像壞掉,而不是像沒有資料)。

同族:`stale` 在量不到時是 `false` —— **不知道不等於舊,也不等於新**。

### ③ 過了門檻要主動說

**日期可見不等於使用者讀得出它壞了。**
「2026-07-31」對多數人只是一個日期,「(70 天前)」才是一句話。
門檻 `STALE_AFTER_DAYS = 3`(釘死成常數,放寬要同時改測試)。

## 策展日期為什麼寫進 `themes/*.md`

`/map` 的「核實」需要一個**在任何環境都成立**的來源。三條路都被排除:

| 方案 | 為什麼不行 |
|---|---|
| build 時算 | `map-index.json` 不進版控(prebuild 現生)→ 沒有「保留前次值」可用 |
| 檔案 mtime | CI clone 之後 mtime = **checkout 時間** → 又一個 build-time 謊言 |
| `git log` | 淺 clone(Vercel)可能查不到 100 天前的 commit → 本機有、線上沒有 |

→ 唯一到處都成立的來源是**已進版控的檔案內容**。
所以每個題材檔都有一行 `**策展日期:** YYYY-MM-DD`,
由 `scripts/build_themes.py` 在重新產生題材頁時自動蓋章
(「重新產生這個題材頁」正好就是「這個題材被策展過」的時刻)。

`tests/freshness.mjs` 檢查**每一個**題材檔都有這一行 —— 少一個,那張卡的標籤就會消失。

---

## 守衛為什麼要掃原始碼

「用錯時鐘」在單元測試裡**看不出來**:兩個時鐘都是合法日期,格式化結果都正確。
所以 `tests/freshness.mjs` 另外掃原始碼,斷言舊寫法不再出現:

- `TodayThemes` 不得再有「報價時間優先於資料時間」那個 fallback
- `/map` 不得再用 `map-index` 的 `generatedAt` 當核實日期

兩條都配一條**對照**(拿舊寫法的字串餵掃描器,確認抓得到)——
否則那兩條在正則寫錯時會是假陰性。

⚠️ 掃描器分不出註解與程式碼。所以**註解裡提到舊寫法時不要寫成可執行的形狀**
(這點在 `tickerFormat` 那次已經踩過一次:regex 字面值的前後斜線)。
